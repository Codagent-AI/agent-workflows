Summary

Implements OpenSpec change create-presentations: browser presentations that develop one continuous diagram through named steps, with a distributable skill for creating and modifying them.

  • Add a style-neutral React scene kit with typed grouped payloads, stable entity motion, fixed-canvas scaling, keyboard/touch navigation, and browse/present modes.
  • Add explicit lazy-loaded presentation routes and the canonical nine-step “How to Use This Skill to Make a Presentation” example, with presentation-owned styling.
  • Package the presentation skill, bootstrap scaffold, and authoring templates, including standalone/monorepo target selection and partial scaffold reuse. Keep vendored kit and script copies aligned.
  • Add production browser verification and settled screenshot capture with advisory overlap, active-navigation, and attribution diagnostics. Include fixes for reference validation, portable scaffold linting, preview process cleanup and signal handling, inspection input validation, and stale capture replacement.

MediumAgent decision

On a very short window the presentation shrinks to nothing

The presentation draws on one tall canvas, 880 by 1280, and scales it to fit the window. In browse mode the controls take 316 pixels of height, so a window about 300 pixels tall leaves no room for the scene.

Checked by acceptance:

  • a desktop window, 1440 by 900
  • a phone, 390 by 900
  • a short window, 780 by 380, where the scene is a sliver

A landscape phone was not checked. Changing the canvas later would change every presentation made with the skill.

QuestionAnswer requiredShould short, wide windows get their own layout?

On GitHubHow the agent decidedThe fit calculation

MediumAgent decision

Verification never sees a presentation the way an audience does

The verifier switches every presentation to browse mode before it checks it, so it never sees present mode, the full-screen view an audience gets. A defect that shows only when presenting would pass verification.

What covers it:

  • Acceptance checked present mode at steps 1, 4 and 9 in a live browser.
  • Nothing checks it when someone makes a new presentation with the skill.
QuestionAnswer requiredShould verification check present mode too?

On GitHubHow the agent decidedThe verifier's mode switch

5
MediumAgent decision

Switching modes can make another presentation on the page jump

When you switch between browse and present mode, the presentation turns off animation for one frame on the whole page, not only for itself. A second presentation on the same page that is moving at that moment jumps to its end instead of animating.

What covers it:

  • A component test checks that switching modes starts no animation, and that the next step still animates.
  • Nothing tests two presentations on one page.
QuestionAnswer requiredWhat should switching modes do to the rest of the page?

On GitHubHow the agent decidedThe mode switch
